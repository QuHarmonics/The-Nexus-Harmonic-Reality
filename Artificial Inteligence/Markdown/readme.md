## Purpose

Architecture notes on agents, reversible execution, BIND contracts, and failures that informed the current system. This collection belongs to the **Artificial Inteligence** research area and should remain identifiable as that area develops.

## Documentation contract

Use Markdown for source derivations, specifications, living notes, and drafts. Mark a document as **draft**, **working**, **superseded**, or **published source** where that distinction matters. Preserve equation numbering and the dependency chain from WHAT to WHERE to ROUTE to inverse.

A Markdown file should identify the version/date when available and link to its evidence or published PDF. Keeping a source file here does not automatically make it a publication.

## Reading rule

**Follow the dependency chain and check the ledger.** An AI-produced explanation is not an execution certificate. Kernel outputs, recorded witnesses, and explicitly checked inverses own those claims.

**Research ledger:** **STANDS** = proved identity or external theorem; **RUNS** = executed readout with stated scope; **OPEN** = missing derivation/link; **DEAD END** = observed landing owned elsewhere; **PULL** = external or physical interpretation. These words are not interchangeable.

## In this research area

- Separate model-generated proposals from native machine outputs.
- Keep tool contracts, input schemas, and certificates with their implementations.
- Preserve complete tests, version changes, and correction records.
- Describe an executed route as RUNS only within its documented test scope.
