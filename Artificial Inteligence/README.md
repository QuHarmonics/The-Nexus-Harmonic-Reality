## What this domain covers

This area covers AI systems used to operate, test, and explain NEXUS—especially reversible kernels, constrained tool interfaces, compiler-side BIND, proof providers, and local-language-model experiments. The language model is a caller or collaborator; it is not the authority that decides whether a mathematical route executed.

**Relationship to the foundation:** the [NEXUS Domain](../The%20Nexus%20Domain/) defines the native machine. Research here explores particular constructions, applications, or comparators without changing that domain by assumption.

## How to read the work

1. Separate model-generated proposals from native machine outputs.
2. Keep tool contracts, input schemas, and certificates with their implementations.
3. Preserve complete tests, version changes, and correction records.
4. Describe an executed route as RUNS only within its documented test scope.

> **Boundary:** An AI-produced explanation is not an execution certificate. Kernel outputs, recorded witnesses, and explicitly checked inverses own those claims.

**Research ledger:** **STANDS** = proved identity or external theorem; **RUNS** = executed readout with stated scope; **OPEN** = missing derivation/link; **DEAD END** = observed landing owned elsewhere; **PULL** = external or physical interpretation. These words are not interchangeable.
