```csharp
    .AddJsonProtocol(o => o.PayloadSerializerOptions.PropertyNameCaseInsensitive = true)
    .WithAutomaticReconnect()
    .Build();
```

Run the desktop app in Debug — you should see messages like:

```

(Trace) HttpConnection connecting to ...
(Error) Failed to connect: ...
```

If you get **no output at all**, your `ConnectWithRetryAsync` isn’t firing or the logger isn’t attached.

### 🧭 3️⃣ Check transport and security policy  
Desktop apps often block unencrypted WebSocket calls.  
Test by forcing LongPolling:

```csharp
.WithUrl(hub.url, opts => { opts.Transports = HttpTransportType.LongPolling; })
```

If that suddenly works, the culprit is the WebSocket handshake.  
Possible causes:
- Corporate proxy or antivirus blocking raw WS traffic.
- Missing `UseWebSockets()` in your ASP.NET server.
- Local firewall denying outbound port.

---

### 🧭 4️⃣ Certificate & HTTPS  
If your local endpoint uses `https://localhost:5001` with a dev certificate, the desktop runtime must trust it.  
Postman ignores cert validation; your app doesn’t.

Try:
```csharp
.WithUrl(hub.url, opts => {
    opts.HttpMessageHandlerFactory = handler =>
    {
        if (handler is HttpClientHandler h)
            h.ServerCertificateCustomValidationCallback = (_,_,_,_) => true;
        return handler;
    };
})
```
If that connects, the issue is certificate trust; install or trust the dev cert.

---

### 🧭 5️⃣ SynchronizationContext gotcha  
`Task.Run` is fine, but if this is called from a constructor or static initializer, the context might not be ready.  
Instead, call `InitializeAsync()` from a known async entrypoint (e.g., `OnStartAsync` in MAUI or WPF).
